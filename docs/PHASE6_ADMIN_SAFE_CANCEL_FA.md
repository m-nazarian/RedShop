# مرحله ششم: Admin Action امن برای لغو سفارش

در این مرحله برای پنل مدیریت Django یک Action امن اضافه شد تا مدیر بتواند سفارش‌های پرداخت‌نشده را از مسیر Service لغو کند.

## دلیل تغییر

بعد از تمرکز منطق موجودی در Service، تغییر دستی وضعیت سفارش در پنل مدیریت دیگر موجودی را برنمی‌گرداند. این رفتار درست است، چون تغییر موجودی باید فقط از مسیر کنترل‌شده و اتمیک انجام شود.

## رفتار جدید

- سفارش پرداخت‌نشده از مسیر `OrderLifecycleService.cancel_unpaid_order` لغو می‌شود.
- موجودی فقط یک‌بار برمی‌گردد.
- سفارش پرداخت‌شده تغییر نمی‌کند.
- پیام مناسب در پنل مدیریت نمایش داده می‌شود.
- تغییر ساده status همچنان موجودی را تغییر نمی‌دهد.

## تست‌ها

دو تست اضافه شد:

- لغو سفارش پرداخت‌شده نباید موجودی را برگرداند.
- Admin Action باید از Service استفاده کند و موجودی را درست آزاد کند.
