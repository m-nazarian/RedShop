# مرحله دهم: مرتب‌سازی ساختار تست‌ها

در این مرحله ساختار تست‌ها استانداردتر شد.

## مشکل قبلی

کلاس `PaymentLifecycleTests` از `CheckoutSecurityTests` ارث‌بری می‌کرد. چون `CheckoutSecurityTests` خودش متدهای `test_` داشت، تمام تست‌های پایه داخل کلاس پرداخت هم دوباره اجرا می‌شدند.

## تغییر انجام‌شده

- یک کلاس پایه به نام `RedShopTestBase` ساخته شد.
- fixture و helper مشترک به این کلاس منتقل شد.
- `CheckoutSecurityTests` فقط تست‌های خودش را اجرا می‌کند.
- `PaymentLifecycleTests` فقط تست‌های پرداخت، لغو سفارش، کوپن و چرخه سفارش را اجرا می‌کند.
- تست‌های تکراری حذف شدند، بدون اینکه پوشش تستی از بین برود.

## نتیجه

Test suite سریع‌تر، خواناتر و قابل نگهداری‌تر شد.
